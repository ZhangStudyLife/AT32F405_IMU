# AT32F405 IMU 串口协议 v1

## 接线与默认配置

USART2，3.3V TTL，8 个数据位、无校验、1 个停止位（8N1），无流控。

| 模块接口脚号 | 信号 | 连接 |
|---|---|---|
| 1 | GND | 接收端 GND |
| 2 | 3V3 | 模块 3.3V 供电 |
| 3 | UART_TX / PA2 | 接收端 RX |
| 4 | UART_RX / PA3 | 接收端 TX |

出厂默认 **2000000 baud、1000 Hz、欧拉角输出**。开机加载已保存的通信和标定参数；旧版仅含标定的记录也能加载，此时通信采用默认值。暂停状态不保存，重启后自动输出。

- 波特率：1000000、2000000、3000000、6000000。
- 输出频率：10、25、50、100、200、250、500、1000 Hz。
- 内部采样和解算始终约 1000 Hz，输出按 1000 / 设置频率抽取完整样本。实际频率跟随采样时钟。
- 每帧线路占用为「帧字节数 × 10 × 输出频率」，超过所选波特率的 80% 时设置失败，原配置不变。
- 常见 CH340 最高支持 2 Mbps；本项目默认兼容该档位。6 Mbps 需要相应接收硬件，不能用 CH340 的测试替代。[CH340 官方规格](https://www.wch.cn/products/CH340.html)

正式固件仅通过 UART 输出数据、接收命令；DAPLink 用于下载。无新样本时不重复发送旧样本。预热阶段仍有数据帧，但有效位为 0；累计 1000 个预热样本后有效。

## 通用帧

所有多字节字段均为**小端**；浮点数为 IEEE 754 float32。以下偏移从完整帧的第 0 字节开始。

| 偏移 | 长度 | 字段 |
|---|---:|---|
| 0 | 2 | 帧头 A5 5A |
| 2 | 1 | 类型：01 数据，10 命令，11 应答，12 主动诊断 |
| 3 | 1 | 载荷字节数 N |
| 4 | 4 | 序号 |
| 8 | N | 载荷 |
| 8+N | 2 | CRC16，低字节在前 |

总长 N+10。数据序号直接使用解算帧号，降频时会按抽样间隔跳号。命令序号由主机指定，应答原样回显。序号和采样时间戳均按 uint32 自然回绕，比较增量时使用无符号减法。

CRC 为 CRC-16/IBM-3740（CCITT-FALSE）：poly=0x1021，init=0xFFFF，refin=false，refout=false，xorout=0。范围为偏移 2 到 7+N，即不包含帧头和 CRC 自身。ASCII 测试串 123456789 的 CRC 为 0x29B1，线上顺序 B1 29。

主机按帧头、长度和 CRC 找帧，不能把一次串口 read 当作一帧。CRC 失败后向后移动一个字节重新找帧，保留末尾不完整部分。遥测不需要应答、不重传；控制端批量解析积压数据，使用最后一帧有效姿态。

## 数据帧（类型 01）

| 载荷偏移 | 长度 | 字段 |
|---|---:|---|
| 0 | 4 | 采样时间 time_us，μs，约 71.6 分钟回绕 |
| 4 | 1 | 状态 flags |
| 5 | 1 | 数据组掩码 mask |
| 6 | 可变 | 按下表 bit0→bit3 顺序排列已启用的数据 |

| 掩码位 | 内容 | float 顺序 | 字节数 |
|---|---|---|---:|
| bit0 / 01 | 欧拉角 | roll、pitch、yaw（°） | 12 |
| bit1 / 02 | 四元数 | w、x、y、z | 16 |
| bit2 / 04 | 原始六轴物理量 | gx、gy、gz（°/s），ax、ay、az（g） | 24 |
| bit3 / 08 | 校正滤波后的六轴 | 同上 | 24 |

mask 允许 01～0F。01 只发送欧拉角，0F 发送全部四组。原始物理量未进行标定和滤波，换算系数为陀螺 0.070 °/s/LSB、加速度 0.000488 g/LSB；量程 ±2000 °/s、±16 g。处理后六轴是送入 Mahony 前的值，不包含 Mahony 内部另行学习的偏置修正。

坐标沿用传感器原生右手坐标；+Z 向上静止时 roll、pitch 为零。四元数描述传感器坐标到相对参考坐标的旋转。roll/yaw 范围约 ±180°，pitch 约 ±90°；yaw 是相对航向。两组加速度都包含重力，不是去重力线加速度。

flags 位定义：

| 位 | 含义 |
|---|---|
| 0 | 姿态有效 |
| 1 | 陀螺已标定 |
| 2 | 加速度已标定 |
| 3 | 标定/采点/求解进行中 |
| 4 | Flash 维护阶段 |
| 5 | 传感器或启动错误 |
| 6 | 尚未完成预热 |
| 7 | 遥测输出已启用 |

默认帧 28 字节，全量帧 92 字节。在 2 Mbps 下线路时间分别约 140 μs、460 μs；在 6 Mbps 下约 46.7 μs、153.3 μs。线路时间不等于程序占用 CPU 的时间，也不包含 USB 和主机调度延迟。

## 命令与应答

命令载荷为「opcode uint8 + 参数」，最大 8 字节。应答载荷为「opcode uint8 + result uint8 + 返回数据」。状态、计时、诊断和校准参数查询带返回数据，其余命令返回数据为空。主机同一时刻只保留一条未完成命令。命令帧不完整超过 10 ms 后接收器重新找帧。

| opcode | 功能 | 参数（不含 opcode） |
|---|---|---|
| 01 | 查询状态 | 无 |
| 02 | 设置通信 | baud uint32 + rate uint16 + mask uint8 |
| 03 | 输出启停 | uint8：0 暂停、1 开启 |
| 04 | 标定操作 | uint8：1 陀螺标定、2 开始加速度标定、3 采集姿态、4 求解、5 取消 |
| 05 | 保存 | 无 |
| 06 | 查询阶段计时 | stage uint8 |
| 07 | 清零计时统计 | 无 |
| 08 | 查询硬件诊断 | 无 |
| 09 | 读取校准参数 | 无 |
| 0A | 重新初始化 IMU | 无 |

result：

| 数值 | 含义 |
|---:|---|
| 0 | 成功；对标定命令表示已接受，最终结果查询状态 |
| 1 | 忙，当前阶段不允许该操作 |
| 2 | 标定姿态不足 |
| 3 | 运动干扰 |
| 4 | 重复姿态 |
| 5 | 求解矩阵奇异 |
| 6 | 标定质量不合格 |
| 7 | 标定超时 |
| 8 | 未知命令或标定操作顺序不正确 |
| 9 | 参数或参数长度非法 |
| 10 | 所选组合超过 80% 带宽预算 |
| 11 | Flash 保存或回读校验失败 |
| 12 | 当前不可用：启动错误，或标定需要的新鲜样本不存在 |

CRC 错误的命令无应答，计入 crc_errors；非法长度和接收异常计入 rx_errors。普通应答超时使用 100 ms，保存使用 1 s。超时后先查询状态，不盲目重复保存、采点等操作。序号用于匹配应答，不提供重复命令去重。

### 状态返回（01）

返回数据为 132 字节：前 31 项 uint32，最后 2 项 float32。下列偏移从应答载荷的第 2 字节，即 opcode/result 后开始计算。

| 偏移 | 名称 | 含义 |
|---:|---|---|
| 0 | version | 线协议版本，当前 1 |
| 4 | baud | 当前波特率 |
| 8 | rate | 当前输出频率 |
| 12 | mask | 当前数据掩码 |
| 16 | flags | 与数据帧相同的状态位 |
| 20 | frames | 已解算帧号 |
| 24 | time_us | 最近采样时间 |
| 28 | heartbeat | 软件毫秒心跳，Flash 维护期间可能漏计 |
| 32 | id | WHO_AM_I，应为 0x70 |
| 36 | sensor_phase | 6 为正常采样，7 为停止/故障，0～5 为初始化 |
| 40 | sensor_error | 0 正常，1 ID 错误，2 复位超时，3 配置回读错误，4 SPI 事务错误 |
| 44 | missed | 估计漏采样数 |
| 48 | late | 有效解算帧超过 500 μs 的次数 |
| 52 | no_data | 无数据/故障事件次数 |
| 56 | invalid | 非法采样间隔次数 |
| 60 | dma_timeouts | SPI DMA 超时数 |
| 64 | dma_errors | SPI DMA 错误数 |
| 68 | overlaps | 未处理 DRDY 被新事件覆盖次数 |
| 72 | tx_dropped | 新输出时机覆盖尚未发送数据的次数 |
| 76 | tx_errors | UART 发送超时或 DMA 错误次数 |
| 80 | rx_errors | UART 接收异常、溢出、非法长度或不完整帧超时次数 |
| 84 | crc_errors | 命令 CRC 错误次数 |
| 88 | cal_mode | 0 空闲，1 陀螺，2 加速度 |
| 92 | cal_state | 0 空闲，1 就绪，2 等待稳定，3 采集，4 求解，5 完成，6 失败 |
| 96 | poses | 已接受姿态数 |
| 100 | samples | 当前阶段样本进度 |
| 104 | stable | 连续稳定样本数 |
| 108 | total_samples | 标定累计样本计数 |
| 112 | cal_error | 标定结果码，沿用 0～8 |
| 116 | solve_steps | 求解步骤数 |
| 120 | save_result | 0 尚无结果，1 保存成功，2 保存失败；启动新保存时清零 |
| 124 | fit_rms | float32，椭球拟合 RMS |
| 128 | max_norm_error | float32，最大模长误差 |

统计不是掉电累计值。tx_dropped 只能反映 MCU 本地待发覆盖；CH340/主机丢帧需要接收端依据帧号和当前抽样间隔判断。正常降频、主动暂停和波特率切换造成的序号跳变不等于接收丢帧。

### 波特率和数据切换（02）

参数整体检查，全部有效后才生效。例如 1 Mbps、1000 Hz、mask=0F 占用 92%，返回 10；2 Mbps 下同一组合占用 46%，允许。

同波特率的修改在应答前生效，正在发送的旧数据帧先完整发送，后续帧携带新的 mask。输出暂停时修改配置仍保持暂停。

改变波特率时，应答使用旧波特率；UART 最后一个停止位发送完成后，等待 20 ms 再应用新速率。在此期间解算继续、遥测暂停。主机收到成功应答后设置自己的新波特率，等待至少 30 ms，再查询状态确认。确认能通信后才发送保存命令。

若切换应答在 MCU 侧发送失败，保留旧波特率。若新速率尚未保存，重新上电恢复上次保存值。CH340 无法访问已保存为 6 Mbps 的模块，需用支持该速率的接收端改回 2 Mbps；通信参数恢复默认可发送 02 设置为 2000000/1000/01 后再发送 05。

### 标定（04）

陀螺：静止放置，发送 04/01，轮询状态。沿用现有静止门限和 60 秒有效样本标定，移动会影响进度。cal_state=5 表示完成，6 表示失败。成功后发送 05 才掉电保留。

加速度：发送 04/02 开始；每次摆好一个姿态后发送 04/03，保持静止，沿用 1.25 秒稳定检测和 5 秒采集。等待状态回到就绪并检查 poses 是否增加，再更换姿态。至少 12 个、最多 128 个不同姿态；发送 04/04 求解，查询 fit_rms、max_norm_error 和结果。成功后显式保存。

04/05 取消标定。失败保留此前有效校正参数。串口程序复用原标定代码，不修改门限、拟合算法或姿态坐标。

### 保存（05）

保存当前通信配置和当前标定参数。标定进行中返回忙。进入维护阶段前结束正在发送的 UART 帧，暂停 IMU 采样和遥测；Flash 写入并回读校验完成后才返回成功应答，随后重新初始化采样并预热。保存暂停时间单独计入阶段 12。

参数区为 0x0801FC00～0x0801FFFF，共 1 KB。新版记录 84 字节：magic=0x4154434C、version=2、原有 64 字节 CalParams、8 字节 UARTConfig、CRC32。UARTConfig 为 baud uint32、rate uint16、mask uint8、reserved uint8=0。CRC32 沿用原存储实现，覆盖 CRC 之前的 80 字节。旧版 76 字节记录只含标定参数，可读且不会自动写回。

下载固件时保留最后 1 KB 参数页；整片擦除会清除通信和标定参数。该记录没有双页掉电事务机制；保存中断电后若 CRC 无效，下次使用默认通信与未标定参数。

### 计时（06、07）

06 返回 41 字节，从 opcode/result 后开始：

| 偏移 | 类型 | 内容 |
|---:|---|---|
| 0 | uint8 | stage |
| 1 | uint32 | core_hz |
| 5 | uint32 | 统计窗口 elapsed_us |
| 9 | uint64 | 窗口内 idle_cycles |
| 17 | uint32 | count |
| 21 | uint32 | last，周期数 |
| 25 | uint32 | min，周期数 |
| 29 | uint32 | max，周期数 |
| 33 | uint64 | total，周期数 |

| stage | 内容 |
|---:|---|
| 0 | DRDY 到 SPI DMA 完成 |
| 1 | 采集驱动 CPU 开销 |
| 2 | 物理量换算及校正 |
| 3 | 滤波 |
| 4 | Mahony |
| 5 | 欧拉角和状态更新 |
| 6 | 标定采样 |
| 7 | 一步标定求解 |
| 8 | 完整求解 |
| 9 | 新样本到解算发布 |
| 10 | 主循环处理，包含 UART，排除 Flash 维护调用 |
| 11 | 原有 DRDY、SPI DMA、SysTick 中断体 |
| 12 | Flash 保存暂停 |
| 13 | UART_Process CPU 开销，排除保存维护 |

耗时 μs = 周期数 × 1000000 / core_hz；平均值使用 total/count。CPU 占用 = 1 - idle_cycles/(elapsed_us × core_hz/1000000)。测量前使用 07 清零，并在小于时间戳回绕周期的窗口内查询。保存、初始化及故障测试与正常运行分别统计；有限测试中的 max 是观察值，不是所有情况的绝对上界。

07 清零计时、CPU 空闲计数及采样周期 min/max，不清零故障计数、通信配置或标定参数。

## 固件入口与验证边界

UART_Init 在 IMU_Init 加载参数之后调用；UART_Process 与 IMU_Process 在同一主循环执行。USART2 TX/RX 使用 DMA1 通道 3/4，SPI 保留通道 1/2。一个 TX 缓冲、一个 256 字节循环 RX 缓冲，命令解析每次预算 64 字节；TX 超时阈值为理论线路时间加 1 ms。

发送繁忙时只保留“需要发送最新数据”的标记，应答优先；不会为慢接收端建立历史帧队列。异常接收重新找帧，实际 DMA 发送期间不改写发送缓冲。

软件测试覆盖协议组合、频率、错帧、计数回绕、发送超时及存储兼容。实板 UART、Flash、CPU 占用和连续运行结论以相应验证报告为准；6 Mbps 外部链路需另用支持它的硬件验证。


## 2026-11-14 故障诊断与标定补充

原有 01～07 命令、132 字节状态应答和数据帧布局保持不变。新增以下命令，均无参数：

| 命令 | 功能 | 成功返回数据 |
|---|---|---|
| 08 | 查询硬件诊断 | 14 个 uint32，小端，见下表 |
| 09 | 读取当前校准参数 | flags:uint32 + 15 个 float32，共 64 字节 |
| 0A | 重新初始化 IMU | 无；接受后异步初始化，可用 01/08 查询 |

新增结果码 **12 = 当前不可用**：没有新鲜六轴数据时，拒绝开始陀螺/加速度标定或采点；主时钟异常时拒绝修改通信配置、保存、重新初始化传感器。取消标定和查询仍可用。0A 会取消正在进行的标定并重新预热，保留已生效的参数和通信设置，不写 Flash，重新建立姿态参考。

### 主动故障提示

无样本、传感器初始化/采集故障，或用户暂停遥测时，每秒主动发送一帧 **类型 12（十六进制）** 的诊断帧。载荷与 08 返回数据相同，但不带命令号/结果码；序号取系统毫秒心跳。仍使用 A5 5A 帧头、长度和 CRC16，总长 66 字节。正常持续输出姿态时不额外发送诊断帧。命令应答优先；保存维护和波特率切换期间暂停主动上报。

接收端应识别类型 01/11/12；不认识的类型按长度与 CRC 跳过，不可把诊断帧当姿态或命令应答。暂停输出只暂停姿态遥测，不关闭查询及故障心跳。

| uint32 索引 | 诊断字段 | 解释 |
|---:|---|---|
| 0 | diagnostic_version | 当前为 1 |
| 1 | boot_error | 0 正常；1 主时钟未达到 216 MHz |
| 2 | core_hz | 当前 CPU 主频 |
| 3 | sensor_phase | 0～5 初始化；6 采集；7 故障/停止 |
| 4 | sensor_error | 0 无；1 WHO_AM_I 错；2 复位超时；3 配置回读不符；4 SPI DMA 超时/错误 |
| 5 | who_am_i | 预期 0x70 |
| 6 | drdy_edges | INT1→PB0 中断累计次数 |
| 7 | fallback_reads | 无中断且 PB0 低时的定时状态补读次数 |
| 8 | last_status | 最近读取的 IMU STATUS_REG；低两位同时为 1 才读取六轴 |
| 9 | pb0_level | 瞬时电平；读到 0 不代表无中断，需比较中断计数增量 |
| 10 | sample_age_us | 最后样本距今微秒数；尚无样本时 FFFFFFFF |
| 11 | flags | 与姿态帧相同的状态位；故障位也覆盖已初始化后的无数据 |
| 12 | config_index | 配置回读所在项，故障排查用 |
| 13 | frames | 累计解算帧号 |

计数自然 uint32 回绕，以无符号差比较；重新初始化不会清除累计中断/补读/错误统计。上电的一次补读不等于硬件损坏，应观察持续增长情况。

INT1 丢失时，驱动约每 1 ms 补读 STATUS_REG，只有加速度和角速度均有新数据才读取、积分；不重复解算旧数据。补读数据的时间戳取查询启动时刻，而不是不存在的中断时刻。补读模式有额外采样时刻误差、可能丢样；不能将它当成正常中断模式的精度或时延验收。恢复 INT1 后自然回到中断触发。SPI 初始化故障仍可串口查询，修复连接后发送 0A 重试。

主时钟失败时仍启动串口诊断，使用 **115200、8N1** 应急速率，不启动 IMU 解算、不保存参数。正常启动继续使用已保存速率，未保存时默认 2 Mbps。此应急分支的软件行为经过模拟测试，真实 PLL 失败尚未实板注入。若 MCU 未上电、持续复位、未执行程序或 TX/RX 物理断路，软件无法保证有回复；指示灯不亮也不能单独判定通信损坏。

### 校准参数读取（09）

64 字节依次为：flags:uint32（bit0 陀螺已标定，bit1 加速度已标定）、gyro_bias[3]（°/s）、accel_bias[3]（g）、matrix[9]（行优先，无量纲）。校正为 g_corrected = g_raw - gyro_bias；a_corrected = matrix × (a_raw - accel_bias)，之后才进入滤波与姿态解算。09 返回当前 RAM 参数；是否已保存请结合保存命令应答和 01 的 save_result 判断。

### 陀螺零偏标定操作

1. 确认 01 的传感器状态正常、数据持续更新，将模块放稳。
2. 发送 04 01；结果 0 仅表示接受。通过 01 查看 mode=1、state。
3. 先等待约 1.5 秒静止检测，再累计 60,000 个有效静止样本（约 60 秒）。运动不算有效样本；累计样本噪声质量不合格则失败，旧参数保留。
4. state=5 表示成功，09 可读到新零偏，flags bit0 置位。state=6 表示失败，查看 cal_error。
5. 确认后发送 05 保存，收到成功应答才表示 Flash 回读验证完成。仅标定成功不会自动保存。

### 加速度椭球标定操作

1. 推荐先完成陀螺标定。发送 04 02，进入 mode=2、state=1（等待用户摆放）。
2. 放稳一个姿态，发送 04 03。每个姿态先约 1.25 秒静止检测，再采集 5,000 个样本（约 5 秒）；运动干扰会重新等待静止。
3. 查询 01，等待返回 state=1，并确认 poses 加一，再换下一个姿态。重复姿态会返回到等待摆放但 poses 不增加，cal_error=4；重新换姿态采集。
4. 至少 12 个分散姿态，最多 128 个。覆盖正负 X/Y/Z 和斜置方向，不能只绕一个轴在同一平面转动。
5. 发送 04 04，进入 state=4 后分步求解；state=5 才成功，state=6 为失败。姿态不足时命令直接返回 2。奇异矩阵、拟合质量不符不会覆盖旧有效参数。
6. 成功后 09 读取偏置和矩阵，flags bit1 置位；确认后发送 05 显式保存。

04 05 可取消当前标定、清空本次采点进度，保留已经生效的参数。采点/陀螺标定期间超过 10 ms 无新数据或驱动故障，会进入 state=6、cal_error=7（超时），保留原参数；恢复数据后重新开始。等待摆放或已开始矩阵求解时，不因无新数据丢弃已有采点。

状态枚举：0 空闲、1 等待摆放、2 等待静止、3 正在采样、4 求解、5 完成、6 失败。查询 01 中的 poses/samples/stable/error 查看进度；正在采集时的“接受”应答不表示采集已完成。
